# 特殊作业评分输出规范

- 只回答当前问题；得分、数量、原因和票据必须来自本轮 Java `18082` 返回。
- 不输出原始 JSON、SQL、内部字段名、工具名、内部 URL 或异常堆栈。
- 总览使用固定标题、总分/满分、通过结论和三个维度得分。
- 单个评分项使用简短段落，不使用表格，包含编号、名称、通过/未通过状态、原因和接口返回的关键事实。
- 三个及以上同类评分项、多个模块或多张问题票才使用简洁表格。
- 无数据时只说“暂未找到可用的评分数据”，不得把无数据写成 0 分。
- 接口失败时只说“当前评分服务暂时不可用，请稍后重试”。
- 评估总结和总结建议必须写完整业务归属，统一使用“特殊作业功能建设模块”“特殊作业数据质量模块”或“特殊作业应用成效模块”，不得只写“功能建设”“数据质量”“应用成效”，也不要使用“板块”或“维度”。总结标题统一使用“评估总结：”，不要使用“情况总结：”。建议只能针对当前回答中的评分项和接口事实，不能串到其他模块。后续每条建议单独一行并以“- ”开头；不要输出 `**`、代码块或其他 Markdown 装饰符号。
- 单独查询一个评分项时，评估总结和建议只围绕该评分项名称，不要写所属维度名称，不要显示 1.1、2.3 等内部序号。
- 单项文字说明中，数据不足直接写“状态为数据不足”，不要附加“（—）”；横杠“—”只用于表格状态列。总结建议标题必须另起一行，标题后的每条建议也必须各占一行。
- 提及三类特殊作业数据时必须写全称：“特殊作业报备数据、特殊作业票数据、特殊作业抽查数据”，不得缩写为“报备、作业票、抽查”。
- 特殊作业应用成效模块中，满分为 0 的项目按扣分项展示：0 分写成“-0.00 / 0.00”，DATA_INSUFFICIENT 状态写成“—”，原因写“无法完成评估”。表格左下角追加说明：“注：对于扣分项，当某项评估指标因数据不足无法完成评估时，该项扣分将全部扣除。”
- 多轮会话可以使用历史摘要理解上下文，但当前得分和原因必须重新查询。
- 深度思考固定使用“第一步、第二步、第三步”，并根据用户当前询问的企业资料、企业评分问题、企业作业票、功能建设、数据质量、应用成效、扣分原因、问题作业票、历史记录或总体评分说明本次核查重点。用户点名具体企业时必须带上企业名称，只说明这家企业本次要查询的内容，不能套用特殊作业整体评分文案。内容要让园区管理人员看得懂，说明将核对什么、最终能看懂什么和如何用于后续处理，不展示技术术语或内部执行细节。
